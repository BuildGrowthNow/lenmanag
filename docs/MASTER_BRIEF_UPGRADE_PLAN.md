# Master Brief & AI Site Generation Upgrade Plan

## Overview

Transform the current deterministic pipeline (extraction → algorithmic brief → static component mapping) into an AI-native system where:

- A **master brief** is the single source of truth, generated by AI from extraction data
- One unified prompt generates the full landing page (content + structure + components)
- AI freely uses and composes from our installed libraries (framer-motion, shadcn, Radix, Tailwind, etc.) and new ones (GSAP, Three.js, Lenis, WebGL)
- Generated sites are compiled at generation time and served as ready-to-render bundles
- The user approves the master brief in the UX, then the full site builds automatically

### 1.2 Server-Side Compilation Service ✅

**Completed:** Production-ready compiler service at `apps/compiler/`

Create a lightweight Node.js compilation service that lives alongside the Next.js app (or as a separate micro-service).

**What it does:**
1. Receives TSX source code (the AI-generated landing page)
2. Compiles it using `esbuild` (fast, <2s) with your installed libraries as externals/bundled
3. Outputs a JS bundle + extracted CSS
4. Returns the compiled assets (or writes to storage)

**Implementation:**

```
apps/compiler/
├── package.json          # esbuild + dependencies
├── src/
│   ├── compile.ts        # Core compilation function
│   ├── server.ts         # HTTP API (POST /compile)
│   └── validate.ts       # Sandbox safety checks (no fs, no network, no eval)
└── Dockerfile
```

**Key decisions:**
- `esbuild` for speed (50-100x faster than webpack)
- External dependencies: React, ReactDOM loaded from shell page
- Bundled dependencies: framer-motion, gsap, three, shadcn components, lenis
- Security: validate that AI output doesn't use `fs`, `fetch`, `eval`, `import()` of external URLs
- Output: ESM bundle + CSS string, stored in your assets bucket (GCS/S3)

**Completed:** `MasterBrief`, `MasterBriefSection`, `BrandAssets` schemas added to `app/schemas/brief.py`

Replace the current `SiteBrief` with a richer AI-generated document:

```python
class MasterBrief(BaseModel):
    id: str
    leadId: str
    version: int
    approvalState: Literal["draft", "needs_review", "approved"]

    # Strategic Foundation
    businessGoal: str              # What this landing page should achieve
    primaryAudience: str           # Who we're talking to
    conversionAction: str          # The one thing we want them to do
    valueProposition: str          # Why they should care (1-2 sentences)
    toneAndVoice: str              # How we sound (casual/professional/bold/etc)

    # Creative Direction
    visualStyle: str               # Description of look/feel (minimal, bold, playful, etc)
    colorStrategy: str             # How colors should be used (dark+neon, soft pastels, etc)
    motionLevel: str               # none / subtle / moderate / dramatic
    specialEffects: list[str]      # ["3d-hero", "parallax-scroll", "particle-bg", etc]

    # Content Blueprint
    headline: str                  # Main hero headline
    subheadline: str               # Supporting line
    sections: list[BriefSection]   # Ordered list of page sections
    ctaStrategy: str               # Primary + secondary CTAs approach

    # Source Material
    extractedContent: dict         # Key content from extraction (proof, services, etc)
    brandAssets: BrandAssets       # Logo URL, colors found, fonts found
    competitorInsights: str        # What competitors do (from extraction)

    # Metadata
    confidenceScore: int
    aiReasoning: str               # Why the AI made these choices (shown to operator)
    createdAt: datetime
    updatedAt: datetime


class BriefSection(BaseModel):
    purpose: str                   # "social-proof", "services", "process", "cta", etc
    headline: str                  # Section headline
    contentSummary: str            # What goes in this section (2-3 sentences)
    suggestedApproach: str         # "testimonial carousel", "bento grid", "timeline", etc
    contentPoints: list[str]       # Key points/items to include
```

## Phase 3: AI Site Generation — One Prompt, Full Page ✅ COMPLETE

**Goal:** Replace the section-by-section deterministic generation with a single AI pass that produces the complete landing page code.

**Status:** ✅ Completed - AI generation integrated into run_generation_job

### 3.1 The Generation Prompt ✅

**Completed:** Full generation prompt implemented in `app/core/ai_site_generation.py`



Once the master brief is approved, ONE prompt generates the entire landing page:

```
You are an expert React developer building a landing page.

## Master Brief
{entire approved master brief}

## Available Libraries
- React 19 with hooks
- Tailwind CSS (utility-first styling)
- framer-motion (animations: motion.div, useScroll, useTransform, AnimatePresence)
- GSAP (timeline animations, ScrollTrigger)
- Three.js via @react-three/fiber and @react-three/drei (3D scenes)
- Lenis (smooth scrolling)
- shadcn/ui components (Button, Card, Badge, Separator, Dialog)
- Radix UI primitives
- Lucide React icons
- embla-carousel-react (carousels)

## Brand Tokens
{colors, fonts, logo URL from extraction}

## Rules
- Export a single default React component
- Use TypeScript/TSX syntax
- All content must come from the brief (no placeholder/lorem ipsum)
- Keep the component self-contained (all sections in one file)
- Use framer-motion for scroll animations and transitions
- Be creative with layout — not every section needs to be full-width
- Mobile responsive via Tailwind breakpoints
- Keep code clean and performant
- Images: use provided URLs from extraction or specify placeholder dimensions
- Aim for a premium, modern look (think Awwwards nominees)

## Output
Return ONLY the TSX code. No markdown, no explanation.
```

### 3.2 Generation Pipeline (Updated) ✅

**Completed:** Integrated into `run_generation_job()` with dual-path logic



```
run_generation_job() new flow:
1. Load approved master brief
2. Load extraction (for content/assets)
3. Call LLM with the generation prompt → get TSX source code
4. Validate source (no dangerous imports, valid JSX structure)
5. Send to compiler service → get compiled bundle
6. If compilation fails → send error back to LLM, ask to fix → retry (max 3)
7. Store: sourceCode, compiledBundleUrl, compilationStatus
8. Generate preview screenshot (Playwright)
9. Run QA scoring on screenshot
10. If quality < threshold → feed QA feedback to LLM → regenerate (auto-iteration)
11. Mark site as ready
```

### 3.3 Quality & Safety ✅

**Completed:** Validation implemented in `_validate_tsx_source()` and compiler service



**Compilation validation:**
- No `import` from URLs or relative paths outside the component
- No `fs`, `child_process`, `eval`, `Function()`, `fetch` to external URLs
- No inline `<script>` tags
- Must export a default component

**Quality checks (post-render):**
- Screenshot QA via Gemini Vision (existing, keep it)
- Lighthouse score (optional, for performance)
- Mobile viewport check (320px, 768px, 1440px)
- Content completeness check: does rendered page contain all brief sections?

### 3.4 Iteration & Self-Correction ✅

**Completed:** `generate_with_retry()` handles automatic retries with error feedback



If the generated site doesn't pass QA:
```
The page you generated has these issues:
{QA feedback - e.g. "hero text is unreadable against background", "section 3 is empty"}

Please fix the TSX code. Here's your previous output:
{previous source code}

Return the corrected TSX.
```

Max 3 auto-iterations. If still failing, mark as "needs_attention" for operator.

## Migration & Rollout Strategy

### Backwards Compatibility
- Keep the current `GeneratedSite` schema fields, add new ones alongside
- Feature flag: `generation_mode: "legacy" | "ai_native"`
- Roll out per-lead or per-tenant

### Data Migration
- Existing briefs don't need migration (new leads use new system)
- Existing generated sites remain as-is (JSON-rendered)
- New sites use the compiled bundle approach

### Rollout Order
1. **Phase 1** first (libraries + compiler) — no user-facing changes, just infrastructure
2. **Phase 2** next (master brief) — can test with internal leads
3. **Phase 3** (AI generation) — the big switch, test thoroughly
4. **Phase 4** (UX) — can be built in parallel with Phase 3
