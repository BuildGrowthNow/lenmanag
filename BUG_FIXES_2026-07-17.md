# Production Bug Fixes - 2026-07-17

## Summary
Fixed 4 critical production bugs in the LenManag/LenQuant platform that were blocking site generation and analysis features.

## Bugs Fixed

### BUG #1 - Analysis Endpoint Missing/Broken ✅
**Issue:**
- LLM analysis endpoint throwing KeyError: 'id'
- GET /api/v1/leads/{lead_id}/extraction/analysis returning 404
- Log message: "LLM analysis failed, continuing with extraction: 'id'"

**Root Cause:**
- In `apps/backend/app/core/leads.py` line 2136, the code was creating a temporary ExtractionSnapshot for LLM analysis without required fields (id, createdAt, updatedAt)

**Fix:**
- Added missing required fields to temp_snapshot creation:
  ```python
  temp_snapshot = self._extraction_doc_to_snapshot(
      {
          "id": f"temp-{lead_id}",  # Added
          **crawl_data,
          "leadId": lead_id,
          "analysis": None,
          "createdAt": _now(),  # Added
          "updatedAt": _now(),  # Added
      }
  )
  ```

**File:** `apps/backend/app/core/leads.py` (line 2135)

---

### BUG #2 - Code Generation Produces Malformed TSX (CRITICAL) ✅
**Issue:**
- ALL generation attempts failing with compilation errors:
  - "Unexpected end of file (LandingPage_XXX.tsx:671:60)"
  - "Unexpected end of file before a closing 'footer' tag"
  - "Expected '>' but found end of file"
- LLM truncating code output before completion

**Root Causes:**
1. Token limit (8192) too low for complete landing pages
2. No detection of truncation errors
3. Generic correction prompt not addressing truncation specifically

**Fixes:**
1. **Increased token limit** from 8192 to 16384 in both generation and retry calls
   - File: `apps/backend/app/core/ai_site_generation.py` (lines 60, 426)

2. **Enhanced correction prompt** to detect and handle truncation:
   - Detects truncation via error message patterns
   - Explicitly instructs LLM to generate COMPLETE code
   - Lists all required sections from master brief
   - Shows what sections were missing
   - File: `apps/backend/app/core/ai_site_generation.py` (_build_correction_prompt)

3. **Improved error logging** with detailed status messages
   - Shows compilation status, error type, validation errors
   - File: `apps/backend/app/core/ai_site_generation.py` (generate_with_retry)

---

### BUG #3 - No Compilation Error Handling ✅
**Issue:**
- System queuing multiple generation jobs on failure instead of using correction prompt
- The `_build_correction_prompt` existed but wasn't being called on compilation (422) errors
- Jobs creating new attempts instead of fixing malformed code

**Root Cause:**
- Site generation was calling `generate_landing_page_code` directly instead of `generate_with_retry`
- No retry logic at the job level

**Fix:**
- Changed site generation to use `generate_with_retry` instead of direct call:
  ```python
  # Before
  from app.core.ai_site_generation import generate_landing_page_code
  result = await generate_landing_page_code(...)

  # After
  from app.core.ai_site_generation import generate_with_retry
  result = await generate_with_retry(
      master_brief=master_brief,
      extraction=extraction,
      site_id=site_id,
      max_retries=3,
  )
  ```

- Enhanced retry logic to detect compilation/validation errors and trigger correction prompt:
  - Checks for `compilation_failed`, `compiler_error`, `validation_failed` statuses
  - Passes full error context (status, validation errors, previous code) to retry
  - Logs detailed error information for debugging

**File:** `apps/backend/app/core/sites.py` (line 3167)

---

### BUG #4 - Playwright Browsers Not Installed ✅
**Issue:**
- Playwright failing to render JS pages with error: "Playwright browsers not installed"
- Extraction falling back to HTML-only mode, reducing quality
- Visual capture features unavailable

**Fix:**
- Installed Chromium browser for Playwright:
  ```bash
  cd apps/backend
  python -m playwright install chromium
  ```

**Status:** Installed successfully
- Playwright version: 1.60.0
- Chromium browser: Installed
